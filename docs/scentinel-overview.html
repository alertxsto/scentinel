1. Latar Belakang & Posisi

Sampah campuran bersifat heterogen. Satu citra atau satu pembacaan gas tidak bisa mewakili seluruh muatan truk. Untuk menentukan di mana inlet sensor harus ditempatkan pada grabber atau bak truk, dibutuhkan pemahaman kuantitatif tentang bagaimana aliran udara dan gas bergerak di sekitar tumpukan sampah.

Scentinel adalah aplikasi desktop native yang menjawab pertanyaan itu: dengan geometri bak tertentu, bentuk tumpukan tertentu, kondisi angin tertentu, dan laju emisi gas tertentu — berapa konsentrasi yang "dilihat" oleh setiap posisi kandidat sensor?

Posisi yang benar

Scentinel adalah alat bantu desain dan screening, bukan pengganti pengukuran lapangan atau uji laboratorium tersertifikasi. Output-nya adalah estimasi dan perbandingan skenario — istilah yang dipakai selalu estimated, proxy, atau screening, bukan klaim nilai tersertifikasi.

Dokumen ini adalah revisi dari rencana JWIS V2. Fokus dipersempit ke satu hal yang bisa dieksekusi dan diverifikasi: layer simulasi CFD. Layer AI fusion, waste passport, dan forecasting pada dokumen sebelumnya adalah visi jangka panjang, bukan scope yang sedang dibangun.

2. Apa yang Dibangun

Aplikasi desktop dengan alur kerja:

  1. Pengguna mendefinisikan penampang 2D bak truk (dimensi via form) dan bentuk tumpukan sampah (preset: flat, mounded, irregular).
  2. Pengguna menempatkan titik kandidat sensor dengan mengklik langsung di viewport 2D.
  3. Pengguna mengatur skenario: kecepatan & arah angin, ventilasi, dan laju emisi per gas (CO, CH4, VOC, H2S) dengan default dari EPA AP-42.
  4. Aplikasi membuat mesh, menulis case OpenFOAM, dan menjalankan solver di container Podman.
  5. Hasil ditampilkan: medan kecepatan, medan konsentrasi per gas, streamline, dan nilai di tiap titik sensor.
  6. Skenario bisa disimpan, dibandingkan, dan diekspor sebagai laporan CSV/PDF.

3.3 Sumber data emisi gas

Semua konsentrasi default berasal dari dokumen resmi EPA dan tersimpan di kode dengan sitasi. Tidak ada angka tanpa sumber.

GasNilai defaultSumber
CO105 ppmv (uncontrolled)EPA AP-42 Ch.2.4 Final Factors (Agu 2024)
CH450% by volumeEPA LMOP — Basic Information about Landfill Gas
VOC / NMOC550 ppmv (as hexane, MSW-only 1992+)EPA AP-42 Table 2.4-2
H2S36 ppmvEPA AP-42 Table 2.4-1
Konteks penting: AP-42 Ch.2.4 juga mencatat bahwa pada kondisi steady-state LFG mengandung ~55% CH4, 40% CO2, 5% N2. Untuk landfill dengan co-disposal limbah non-domestik, default NMOC naik ke 2.400 ppmv. Scentinel menyediakan kedua rezim ini sebagai pilihan, bukan hanya satu angka.

4. Protokol Verifikasi

Simulasi tanpa verifikasi tidak lebih dari animasi. Empat uji berikut adalah gate yang harus lolos sebelum hasil simulasi dianggap layak dipakai:

UjiMetodeKriteria lulus
Mass balance Integrasi fluks scalar keluar vs fluks sumber pada kondisi steady Error < 5%
Mesh independence Refine mesh 2×, bandingkan nilai di titik probe Deviasi < 10%
Benchmark analitik Kasus difusi 1D vs solusi erfc R² > 0.99
Benchmark solver Lid-driven cavity case jalan sampai selesai Residual sesuai, tanpa FOAM FATAL

5. Roadmap Eksekusi

FaseIsiExit criteria
F0 Skeleton aplikasi + integrasi container OpenFOAM + benchmark cavity Solver jalan dari aplikasi, hasil tampil di UI
F1 Geometri 2D + meshing + klik sensor + save/load project Satu skenario jalan end-to-end
F2 Multi-gas scalar + visualisasi + probe + uji verifikasi fisika CO/CH4/VOC terukur di titik sensor, semua uji verifikasi lolos
F3 Perbandingan skenario + export laporan Bisa bandingkan ≥2 run, export CSV/PDF
F4 Geometri 3D + analisis transient (response delay) Mesh 3D jalan, response delay terukur
Sprint 2–4 minggu pertama
  • Setup environment: venv, dependensi, container OpenFOAM
  • Benchmark cavity untuk validasi pipeline container
  • Geometri 2D bak truk + tumpukan sampah + meshing
  • Case generation dengan satu gas (CO) + run pertama end-to-end
  • Review hasil dengan pembimbing sebelum lanjut ke multi-gas

6. Risiko & Mitigasi

RisikoMitigasi
VTK + Qt6 bermasalah di Wayland Uji sejak F0; fallback ke QT_QPA_PLATFORM=xcb atau render offscreen
Mesh dari gmsh ditolak OpenFOAM Boundary tagging diuji ketat; checkMesh sebagai gate wajib
Solver run lama membekukan UI Log streaming async via QThread sejak F0
Angka source term dianggap asumsi Semua default dari AP-42/LMOP dengan sitasi di kode dan dokumen
Scope creep kembali ke AI/fleet layer Fokus ketat pada layer simulasi sampai F3 selesai dan terverifikasi
Hardware grabber dipasang terlalu dini Bench rig → pilot terkendali → field pod, setelah simulasi tervalidasi
